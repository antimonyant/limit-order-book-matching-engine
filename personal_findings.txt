1. A limit order book is a real-time record of all unexecuted buy and sell orders. It's primary focus is to
    automatically match buyers and sellers when prices align. (The Steam Market might be an example!)
    Notably, the order book prioritizes the highest buy price (best bid) and the lowest sell price (best ask).
    This means orders are matched by best price first and timestamp second.
2. Crossing price
    This is the price at which a broker matches a buy order and a sell order from two different clients.
    Crosses when a buy is >= best sell price or when a sell is <= best buy price
    Trades happen at the best price level and not at the proposed order price
3. CMakeLists vs makefile
    CMakeLists create makefiles that build your project. They also automatically find the correct dependencies
    based on the type of system you have. Much better to build a CMakeLists file then multiple makefiles
4. Designated initializers C++ 20 feature
    Can initialize objects like structs by using the member names inside braced initialization lists
    For example:
    Trade trade{
            .price = resting_order.price,
            .quantity = trade_amount,
            .buy_order_id = order.is_buy ? order.id : resting_order.id,
            .sell_order_id = order.is_buy ? resting_order.id : order.id};
5. Standard in CMakeLists to FetchContent testing frameworks like GoogleTest through its Github link. 
    This means at Cmake configure time, Cmake downloads the GoogleTest source code which can then be linked to
    from the test executable.

Design Decisions
1. Orderbook holds orders in a map sorted by price levels. O(logn) insert/remove O(1) access to min/max
2. Each price level in the map has a deque that is kept FIFO in order to ensure price time priority
3. Two maps, one to hold only buys and the other holds only sells
4. Timestamp and ID are assigned by the orderbook as private counters and not by the users
5. add_order returns the assigned ID for cancellations
6. best_bid() and best_ask() return -1.0 if there are no orders
7. An unfilled marker order is dropped (IOC-style fill what you can, cancel rest)
8. Partial fills mutate the resting order in place otherwise FIFO ordering could be broken
9. Erase empty price levels or best_bid()/best_ask() could return an empty deque price level
10. Recomputes the best price level within the loop (in match_order) so multiple level walks can occur
